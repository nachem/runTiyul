# RunTiyul v1.4.1

Release status: [published 2026-09-22](https://github.com/nachem/runTiyul/releases/tag/v1.4.1)<br>
App version: `1.4.1+11`

This update improves recovery from delayed GPS fixes and preserves the runner's
chosen map zoom. It also includes map, route-editing, routing, and
download-stability improvements since v1.4.0.

## Highlights

- **ACT-004:** elapsed-time-aware GPS filtering accepts plausible delayed fixes
  instead of permanently rejecting later positions beyond a fixed 200 m jump.
  After a five-minute gap, the first accepted fix adds no distance across the
  unknown interval.
- **ACT-007:** a GPS-stream error pauses recording and reports the failure.
- **NAV-005:** Running direction retains course-up orientation; pinch and
  double-tap zoom no longer disable Follow position. A one-finger pan stops
  following without changing the selected orientation.
- **MAP-008:** current-location recenter and recording follow updates preserve
  the live zoom level. Initial neighborhood centering and explicit Fit remain
  separate camera actions; there is no speed-based automatic zoom.
- **OFF-005/OFF-009:** raster downloads use provider-specific pacing, batch
  breaks, and shared persisted `Retry-After` cooldowns. Pause interrupts waits
  and stops new retries; long cooldowns and permission refusals leave a
  resumable paused area without bypassing the provider's deadline.
- Additional hardening includes independent vector-way comparison,
  sparse editing that preserves dense route geometry, stricter connected trail
  matching, bounded forward recovery, and offline-download/storage stability.
  See [implementation status](../02-implementation-status.md) for details and
  the limits of the loaded map data.

## Licensing and Limitations

- No provider permissions are granted by this update. Standard release defaults
  remain in effect; the separately authorized Topographic/Satellite raster
  download flag is not enabled for this build.
- Battery Saver, screen-lock recording, outdoor heading/camera behavior, and
  these changes' effects on physical-device performance remain unverified.
- Android can still restrict or stop background work. Delayed-fix resilience is
  not a guarantee of uninterrupted location delivery or accurate missing track
  reconstruction.
- Raster pacing does not apply to interactive map browsing, vector downloads,
  or terrain requests. Actual provider limits still require verification.
- The unsigned iOS artifact built successfully on the macOS runner; runtime
  and sideloading remain unverified.
- Production offline-map provider approval, reliable offline routing coverage,
  free-space checks, and the existing device-validation gates remain open.
