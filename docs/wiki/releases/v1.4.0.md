# RunTiyul v1.4.0

Release status: [published 2026-08-20](https://github.com/nachem/runTiyul/releases/tag/v1.4.0)<br>
App version: `1.4.0+10`

RunTiyul v1.4.0 makes trail navigation more deliberate: recovery stays on
recognized mapped ways and reconnects ahead, maneuver prompts describe the real
turn geometry, saved routes can be cleaned and aligned, and the recording map
can continuously follow the runner in north-up or running-direction mode.

## Highlights

### Forward mapped-way recovery

- Searches the locally loaded trail/road graph for a connected path that rejoins
  the planned route beyond completed progress.
- Rejects disconnected open-terrain bridges, trims at the first ahead contact,
  and rejects an initial direction outside a 75-degree forward cone.
- Draws the recovery as a distinct solid path. Voice and visual guidance never
  tell the runner to go behind or return to the deviation point.
- Tells the runner to remain on a recognized path while searching when no safe
  forward connection is available.

### Precise maneuver guidance

- Detects mapped junction decisions and significant geometry bends, including
  intentional U-turns.
- Announces rounded angles such as "bear right 45 degrees," plus sharp-turn and
  U-turn wording even when the named trail does not change.
- Alerts once in advance and again at the turn apex.
- Combines a second maneuver within 45 meters as "then immediately ...".
- Keeps a 25-meter overshoot grace so promptly joining the correct outgoing path
  does not create a false missed-waypoint state or re-arm from GPS jitter.

### Cleaner and trail-aligned routes

- Removes tightly bounded mini out-and-back junction artifacts while preserving
  larger intentional double-backs.
- Adds **Snap to trails** to every saved manual and GPX route.
- Requires a connected recognized trail/road graph end-to-end; it never calls a
  straight off-network bridge snapped.
- Preserves route identity/source and matching optional GPX point metadata, and
  reports updated, already aligned, unavailable, and failure outcomes.

### Recording map and Back navigation

- Adds persistent Follow position and **North up** / **Running direction** map
  controls to recording.
- Uses a quality-filtered moving course and atomically recenters/rotates the map;
  panning stops position following but keeps the selected orientation.
- Makes system Back return through primary destination history and pushed
  screens. The app can close only from the root Map destination.

## Known Limitations

- Forward recovery requires the runner and reconnect point to be represented in
  the currently loaded vector trail/road graph and a reliable moving course. It
  deliberately produces no invented shortcut when those conditions are absent.
- Recovery geometry, prompt timing, GPS heading quality, camera follow/rotation,
  outdoor audio, Bluetooth/open-ear routing, and locked-screen behavior remain
  unverified on a physical device.
- iOS runtime and unsigned IPA sideloading remain unverified.
- Production offline-map provider approval and physical background-recording
  verification remain unresolved.
