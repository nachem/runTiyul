# RunTiyul v1.4.7

Release status: candidate prepared 2026-09-28<br>
App version: `1.4.7+17`

This update makes intentional out-and-back routes easier to create and follow,
and adds explicit guidance back to the run start or another point on the active
route without ending the recording.

## Changes

- **RTE-003:** route creation now offers **Return to start** after two distinct
  controls. A selected control can also be appended as a return target. Both
  actions use the active Checkpoints or Follow trails planner, retain direct
  segment diagnostics, remain undoable, and save the displayed geometry.
- **NAV-002:** overlapping outbound and return legs now use prior monotonic
  progress plus reliable moving heading to select the correct route segment.
  A bounded near-turnaround fallback handles a temporarily missing heading
  without allowing arbitrary jumps to a distant crossing.
- **NAV-011:** the recording screen now offers **Navigate back**. Routed runs
  can choose **Home / start** or tap a point on the active route; free runs can
  retrace accepted recorded breadcrumbs.
- Return guidance shows a highlighted remaining path, direction arrow,
  destination marker, remaining distance, and arrival state. **Resume route**
  cancels the temporary override and restores original route progress.
- Return guidance never edits the saved route or its activity relationship.
  Automatic off-route recovery remains mapped and forward-only; backtracking
  occurs only after the runner explicitly requests it.

## Mobile Checks and Limitations

- On a phone, create an overlapping out-and-back with **Return to start** and
  cross the turnaround with and without a reliable heading.
- During a routed run, try Home/start and a selected route point; during a free
  run, verify the breadcrumb retrace. Confirm the guidance line trims with
  movement and Resume route restores the original plan.
- An active temporary destination is not restored after process death. A
  recovered paused activity can request a new plan from its last saved sample.
- Same-route slicing and recorded breadcrumbs do not establish walkability,
  legal access, complete map coverage, or rescue-grade guidance.
- Physical-device GPS/heading behavior, background/locked-screen operation,
  data-preserving installation, and iOS runtime remain unverified.
- Provider permissions, dependencies, schema, cache format, signing identity,
  and location privacy are unchanged.
