# RunTiyul v1.4.6

Release status: candidate validated on 2026-09-24; hosted checks and publication pending<br>
App version: `1.4.6+16`

This update improves snapping on winding paths and tracks, preserving selected
hairpin endpoints instead of moving them to a shorter nearby road.

## Changes

- **RTE-003/RTE-011:** separate nearby arms of a single curved trail remain
  available as snap candidates. Neighboring route points can choose a
  consistent arm rather than taking an unnecessary hairpin detour.
- Among equally connected plans, snaps already within 2 m take priority over
  a shorter route that moves the selected points. This applies equally to
  roads and trails, and does not prevent alternatives when an exact fragment
  cannot connect.
- **RTE-012:** Follow trails retains exact endpoints on opposite hairpin arms
  in both directions, instead of collapsing the second endpoint into the first.
- Saved-route snapping preserves the selected trail bend, route identity,
  and matching endpoint elevation/timestamp metadata.
- Candidate limits, graph connectivity, access/grade checks, explicit
  unmapped-gap handling, and strict navigation-recovery rules are unchanged.

## Validation

- Fresh version-candidate full VS Code Flutter test run: all 365 tests passed.
- Read-only Dart format check: 105 files checked, zero changes.
- `flutter analyze --no-pub`: no issues; version and release-note metadata match.
- The preceding implementation also built an Android debug APK on 2026-09-24.
  The existing `flutter_tts` Kotlin warning is non-fatal.
- Device discovery listed Windows, Chrome, and Edge only. No mobile device was
  installed or tested. Hosted CI, signed release builds, and independent public
  artifact verification remain pending.

Coverage includes path/track hairpin arms, near-exact road/trail taps beside
shortcuts, noisy middle checkpoints, dense-vertex candidate bounds, both
Follow-trails directions, and SQLite save/reload with endpoint metadata.
Synthetic vector-tile tests verify footways, steps, and tracks as adjoining
and multipart lines through connected routing and turn generation; restricted
paths remain excluded. No extractor or turn-engine change was needed.

## Mobile Checks and Limitations

- Check the same problematic path/track in Checkpoints and Follow trails. Tap
  opposite hairpin arms, reverse direction, compare with a nearby road, then
  save/reopen and check the turn geometry.
- Automated scenarios are synthetic, not confirmation that the reported real
  trail is covered. No failing GPX or map location was provided. Missing vector
  geometry, topology, access data, and tile-boundary gaps can still affect routes.
- Direct and short-gap planning connections are not verified walkable paths
  or permission to cross private land. Device performance, outdoor behavior,
  data-preserving installation, and iOS runtime remain unverified.
- Provider permissions, dependencies, schema, cache format, signing identity,
  and location privacy are unchanged. Public builds retain ordinary provider
  gates; Esri offline downloads still require the separately authorized DEV
  build and on-device confirmation.
